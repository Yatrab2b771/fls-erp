# Deploying FLS ERP — free, no credit card

Three free services, wired together:

1. **[Neon](https://neon.tech)** — the Postgres database
2. **[Render](https://render.com)** — the API (`apps/api`, Express)
3. **[Netlify](https://netlify.com)** (or [Vercel](https://vercel.com)) — the web app (`apps/web`, React/Vite). Either works the same way; this guide uses Netlify.

All three have a free tier that doesn't ask for a card. Total time: ~15 minutes.

---

## 0. Push this repo to GitHub

Render and Vercel both deploy by connecting to a GitHub repo.

```bash
git init
git add .
git commit -m "Initial commit"
```

Then create a new **private** repo on GitHub (github.com → New repository) and push:

```bash
git remote add origin https://github.com/<your-username>/<repo-name>.git
git branch -M main
git push -u origin main
```

---

## 1. Database — Neon

1. Sign up at [neon.tech](https://neon.tech) (GitHub login works).
2. Create a project (any name/region).
3. On the project dashboard, copy the **connection string** — it looks like:
   `postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require`
4. Keep this tab open — you'll paste this as `DATABASE_URL` in the next step.

---

## 2. API — Render

1. Sign up at [render.com](https://render.com) (GitHub login works) and connect your GitHub account.
2. **New → Blueprint**, pick this repo — Render reads [`render.yaml`](render.yaml) at the repo root and pre-fills a web service (`fls-erp-api`) on the free plan.
3. When prompted, fill in the env vars marked "from env" / secret:
   - `DATABASE_URL` — the Neon connection string from step 1
   - `SEED_ADMIN_EMAIL` — e.g. `admin@fls.local`
   - `SEED_ADMIN_PASSWORD` — a real password, not the repo's dev default
   - `SEED_DEMO_PASSWORD` — a real password for the demo department accounts
   - `FRONTEND_URL` — leave blank for now, you'll come back and set it after step 3 (once you know the Vercel URL)
   - `JWT_SECRET` is auto-generated by Render — leave it.
4. Deploy. Render runs `npm install`, builds the API, and runs `prisma migrate deploy` against Neon automatically (see `buildCommand` in `render.yaml`).
5. Once live, note the service URL — something like `https://fls-erp-api.onrender.com`. Check `https://fls-erp-api.onrender.com/health` returns `{"ok":true}`.
6. **Seed demo data** (admin login + department users + a couple of sample orders): open the service's **Shell** tab in the Render dashboard and run:
   ```bash
   npm run db:seed --workspace apps/api
   ```

---

## 3. Web — Netlify

1. Sign up at [netlify.com](https://netlify.com) (GitHub login works) and authorize it to access your GitHub repos.
2. **Add new site → Import an existing project → Deploy with GitHub**, pick this repo.
3. Netlify reads [`netlify.toml`](netlify.toml) at the repo root and pre-fills the build command/publish directory — leave those as detected, don't type your own.
4. Before deploying, add one environment variable (there's a "New environment variable" option on this same screen, or add it after under **Site configuration → Environment variables**):
   - `VITE_API_URL` = your Render API URL from step 2 (e.g. `https://fls-erp-api.onrender.com`, **no trailing slash**)
5. Deploy. You'll get a URL like `https://fls-erp.netlify.app` — that's the link for your boss. (You can rename the site — **Site configuration → Change site name** — for a nicer URL.)

If you'd rather use Vercel instead: **Add New → Project**, import this repo, set **Root Directory** to `apps/web` (it reads `apps/web/vercel.json` automatically), same `VITE_API_URL` env var, deploy.

---

## 4. Lock CORS to the real frontend URL

Now that you have the Netlify URL, go back to the Render service → **Environment**, set:

- `FRONTEND_URL` = your Netlify URL (e.g. `https://fls-erp.netlify.app`)

Save — Render redeploys automatically. Without this, the API accepts requests from any origin (not a real risk since auth is a bearer token, not a cookie, but worth tightening once you know the real URL).

---

## Log in

Open the Netlify URL and log in with the admin credentials you set in step 2
(`SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`), or one of the seeded demo
department accounts (`bd@fls.local`, `ppic@fls.local`, `store@fls.local`,
etc. — password is whatever you set as `SEED_DEMO_PASSWORD`).

---

## Known limitations of this free setup

- **Render free web service sleeps after 15 minutes idle.** The first
  request after that takes ~30–50s to wake it back up — expected on the
  free tier, not a bug. Fine for a demo link; upgrade the Render plan
  (or ping it periodically) if that's a problem later.
- **Uploaded PO documents (photos/PDFs) don't persist.** Render's free
  web service has an ephemeral disk — uploaded files are lost on
  redeploy/restart. Fine for a demo; real use would need object storage
  (S3/R2) instead of local disk — not set up here.
- **Neon's free Postgres** has generous limits and no fixed expiry
  (unlike Render's own free Postgres, which expires after a set window —
  that's why this guide uses Neon instead).
